Causes

DXFの文字化けの、よくある3つの原因

DXF の文字コードは、版によって決まりがちがいます。
図面を作った道具と、開く CAD の組み合わせで、次のような化けが起きます。

  1. UTF-8 と Shift_JIS の食い違いR2007 より新しい版の DXF は、中身が UTF-8 の決まりです。
    Jw_cad は Shift_JIS で読むので、日本語が「蟷ｳ髱｢蝗ｳ」のように化けます。
    逆に、新しい版なのに中身が Shift_JIS の DXF もあります。
  2. $DWGCODEPAGE のまちがいR12〜R2004 の DXF は、$DWGCODEPAGE に書いた文字コードで読む決まりです。
    ANSI_1252 と書いてあるのに中身が Shift_JIS だと、「•½–Ê}」のように化けます。
    書いた値が中身と合っていれば、この道具はその値を信じます。
  3. 化けた文字が、そのまま保存されたほかの道具が一度まちがえて読み、そのまま保存すると、化けが文字に焼きつきます。
    「ã‚·ãƒ§ãƒ¼」のような ã型や、二重・三重の化けもあります。
    \U+5E73 のような書き方も、字に戻します。

Scope

直せる物と、直せない物

直せる物と直せない物
文字化けの形この道具で
版と文字コードの食い違い（UTF-8・Shift_JIS）直せます。1 本の中に文字コードが混ざった物も、行ごとに読み分けます。
$DWGCODEPAGE のまちがい直せます。中身と矛盾しなければ、書いてある値を信じます（半角カナだけの図面や、西欧語・ロシア語の図面を壊しません）。
焼きついた化け（縺繧型・ã型・ƒ型）と二重・三重の化け直せます。
\U+XXXX・\M+1XXXX の書き方字に戻します。
化ける途中で元の文字が「�」に置きかわった物前後の字から決めきれる所だけ直し、決めきれない所は「直せませんでした」と出して元のまま残します。
バイナリ形式の DXF・DWG読めません。CAD で ASCII 形式の DXF に保存し直してください。
書体（フォント）が無いことによる化けWindows に無い書体は、MS ゴシックなど Windows にある書体に置きかえます。表示の大きさのずれまでは直しません。

Jw_cad 向けに新しい版から R12 にするとき、R12 に無いハッチは書き出しません（保存のときにお知らせします）。

FAQ

よくある質問

DXF のファイルは、どこかに送られますか？

送りません。
ファイルは、お使いのブラウザの中だけで読んで直します。
サーバーには何も送りません。

Jw_cad で DXF の文字が化けるのは、なぜですか？

Jw_cad は DXF の文字を Shift_JIS として読みます。
R2007 より新しい版の DXF は中身が UTF-8 なので、そのまま開くと日本語が化けます。
この道具で「Jw_cad 向け」（R12・Shift_JIS）で保存し直すと読めるようになります。

どんな文字化けを直せますか？

UTF-8 と Shift_JIS の食い違い、$DWGCODEPAGE のまちがい、ほかの道具が一度まちがえて読んで保存した化け（縺繧型・ã型・ƒ型と、その二重・三重の化け）、\U+XXXX の書き方です。

直せない文字化けはありますか？

化ける途中で元の文字が「?」や「�」に置きかわって消えた所は、元に戻せないことがあります。
その所は「直せませんでした」と理由を出し、まちがった字は入れません。
バイナリ形式の DXF と DWG は読めません。
